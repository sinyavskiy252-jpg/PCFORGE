# PCFORGE: инструкция для новичка (Windows)

Иди по порядку. Не переходи к следующему шагу, пока не закончишь текущий. Все команды ниже вводятся в **PowerShell**, если отдельно не написано обратное.

## Шаг 1. Распакуй проект

1. Скачай архив `PCFORGE_fullstack_SQLServer_fixed.zip`.
2. Нажми по нему правой кнопкой мыши → «Извлечь всё…».
3. Открой получившуюся папку `PCFORGE_fullstack_SQLServer`.
4. Внутри должны быть папки `backend`, `frontend`, `database`, `tests`, `.github` и файлы `Dockerfile`, `docker-compose.yml`, `README.md`.

## Шаг 2. Установи нужные программы

1. **Python 3.12 или новее.** Скачай с https://www.python.org/downloads/windows/ . При установке отметь галочку **Add python.exe to PATH**.
2. **SQL Server.** Если уже установлен, ничего повторно ставить не нужно. Если нет, выбери SQL Server Express с официальной страницы Microsoft: https://www.microsoft.com/en-us/sql-server/sql-server-downloads .
3. **SQL Server Management Studio (SSMS).** Это программа для открытия и выполнения SQL-файла: https://learn.microsoft.com/en-us/ssms/install/install .
4. **Microsoft ODBC Driver 18 for SQL Server.** Он нужен Python для связи с SQL Server: https://learn.microsoft.com/en-us/sql/connect/odbc/download-odbc-driver-for-sql-server .
5. **Git:** https://git-scm.com/download/win .
6. **Docker Desktop:** https://docs.docker.com/desktop/setup/install/windows-install/ . Для Docker Desktop на Windows может потребоваться WSL 2; установщик подскажет, если его не хватает.
7. **Visual Studio Code** (необязательно, но удобно): https://code.visualstudio.com/ .

После установки Docker Desktop запусти его и дождись, пока он покажет, что Docker работает.

## Шаг 3. Проверь Python и Git

1. Открой папку проекта в Проводнике.
2. Щёлкни по адресной строке папки, напиши `powershell` и нажми Enter. Откроется терминал уже в нужной папке.
3. По одной выполни команды:

   ```powershell
   py --version
   git --version
   docker --version
   docker compose version
   ```

Если какая-то команда пишет, что не найдена, значит программа не установлена или терминал был открыт до установки. Установи её/перезапусти PowerShell и повтори.

## Шаг 4. Создай базу данных

**Этот шаг выполняется один раз, только если базы PCFORGE ещё нет или её нужно создать заново.** Скрипт удаляет и пересоздаёт таблицы внутри базы `PCFORGE`, поэтому не запускай его бездумно повторно, если там есть нужные данные.

1. Открой SQL Server Management Studio (SSMS).
2. В окне **Connect to Server**:
   - Server type: `Database Engine`.
   - Server name: попробуй `localhost\SQLEXPRESS`, если устанавливали SQL Server Express с экземпляром SQLEXPRESS. Если у тебя другое имя сервера, используй его.
   - Authentication: выбери `Windows Authentication`, если так входишь в SQL Server.
3. Нажми **Connect**.
4. В SSMS выбери **File → Open → File**, найди файл `database/PCFORGE.sql` в папке проекта.
5. Вверху окна запроса проверь, что открыт правильный файл, затем нажми **Execute** или клавишу **F5**.
6. Внизу должна появиться вкладка **Messages** без красных ошибок. В Object Explorer нажми правой кнопкой на **Databases → Refresh**. Должна появиться база `PCFORGE`.
7. Раскрой `PCFORGE → Tables`. Должны быть таблицы `dbo.Users`, `dbo.Categories`, `dbo.Components`, `dbo.Builds`, `dbo.BuildComponents`, `dbo.CompatibilityRules`, `dbo.Orders`.

Если SSMS не подключается, не продолжай к запуску приложения: сначала исправь подключение к SQL Server. Частая причина — в поле Server name указано не то имя экземпляра.

## Шаг 5. Настрой приложение для локального запуска

1. В папке проекта найди `.env.example`.
2. Скопируй его в той же папке и назови копию `.env` (именно `.env`, без `.txt`). Не переименовывай сам `.env.example`.
3. Открой `.env` в Блокноте. Для Windows Authentication на локальном компьютере обычно оставь так:

   ```dotenv
   SQL_SERVER=localhost\SQLEXPRESS
   SQL_DATABASE=PCFORGE
   SQL_DRIVER=ODBC Driver 18 for SQL Server
   SQL_TRUSTED_CONNECTION=yes
   ```

4. Если имя экземпляра в SSMS было другим, укажи это же имя в `SQL_SERVER`.
5. Сохрани файл. Не отправляй `.env` в GitHub — он исключён из Git.

## Шаг 6. Установи библиотеки Python

В том же PowerShell, в корне проекта, выполни команды по одной:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
py -m pip install --upgrade pip
py -m pip install -r backend/requirements.txt
```

Если PowerShell запретит запуск скрипта активации, выполни только в текущем окне:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

Потом снова выполни установку зависимостей, если она ещё не завершилась. Успешно активированное окружение обычно показывает `(.venv)` слева от строки терминала.

## Шаг 7. Запусти тесты

В PowerShell из корня проекта:

```powershell
py -m pytest -q
```

Если тесты завершились с сообщением `2 passed`, это означает, что базовые тесты проходят. Эти тесты проверяют только простые вещи, а не всю функциональность приложения.

## Шаг 8. Запусти сайт без Docker

1. Выполни:

   ```powershell
   py backend/app.py
   ```

2. Не закрывай это окно PowerShell — в нём работает сервер.
3. Открой браузер и введи `http://localhost:5000`.
4. Для проверки подключения к базе открой `http://localhost:5000/api/health`.
   - Если увидел `"status":"ok"`, приложение связалось с SQL Server.
   - Если `"status":"error"`, посмотри текст `error` в ответе. Проверь имя сервера, что служба SQL Server запущена, что база `PCFORGE` существует и что установлен ODBC Driver 18.
5. Для проверки данных открой `http://localhost:5000/api/categories`, затем `http://localhost:5000/api/components`.
6. Чтобы остановить сервер, вернись в PowerShell и нажми `Ctrl+C`.

**Сначала добейся работы сайта локально.** Не переходи к Docker, пока локальный запуск не заработал.

## Шаг 9. Подготовь SQL Server для Docker (отдельно от локального запуска)

В контейнере Linux нельзя просто использовать Windows Authentication твоего пользователя Windows. Для Docker нужен SQL Server, доступный по TCP, и SQL Authentication.

1. Открой **SQL Server Configuration Manager**.
2. Перейди в **SQL Server Network Configuration → Protocols for твой экземпляр**.
3. Включи **TCP/IP**.
4. В свойствах TCP/IP открой вкладку **IP Addresses**. В секции **IPAll** укажи пустое поле **TCP Dynamic Ports** и `1433` в **TCP Port** (если порт 1433 свободен и подходит для твоей конфигурации).
5. Перезапусти службу SQL Server для своего экземпляра через SQL Server Configuration Manager или Services.
6. В SSMS нажми правой кнопкой на имя сервера → **Properties → Security** и включи **SQL Server and Windows Authentication mode** (Mixed Mode), если SQL Authentication ещё не включена.
7. Перезапусти службу SQL Server после смены режима.
8. Создай или используй SQL-логин с паролем и доступом к базе `PCFORGE`. Для учебной работы лучше создать отдельный логин, а не использовать встроенный `sa`. В SSMS: **Security → Logins → New Login…**; выбери SQL Server authentication, задай пароль, затем в **User Mapping** отметь `PCFORGE` и выдай нужные права для учебного проекта.
9. Если подключение не работает, проверь брандмауэр Windows и разреши входящие TCP-подключения на выбранный порт только в нужной сети. Не открывай порт в интернет.

## Шаг 10. Запусти Docker

1. Запусти Docker Desktop и дождись состояния **Running**.
2. Открой PowerShell в корне проекта.
3. Укажи пароль SQL-логина в текущем окне PowerShell (подставь свой реальный пароль, не слово из примера):

   ```powershell
   $env:SQL_PASSWORD = "ТВОЙ_РЕАЛЬНЫЙ_ПАРОЛЬ"
   $env:SQL_USERNAME = "ИМЯ_ТВОЕГО_SQL_ЛОГИНА"
   $env:SQL_SERVER_DOCKER = "host.docker.internal,1433"
   ```

4. Проверь конфигурацию:

   ```powershell
   docker compose config
   ```

   Если команда вывела итоговую конфигурацию без ошибки — хорошо. Не копируй её публично: в ней может быть пароль.

5. Собери и запусти контейнер:

   ```powershell
   docker compose up --build
   ```

   Первый запуск может занять несколько минут, потому что Docker скачивает базовый образ и устанавливает драйвер SQL Server.

6. Когда сборка завершится, открой `http://localhost:5000`, затем `http://localhost:5000/api/health`.
7. Останови контейнер сочетанием `Ctrl+C`, затем выполни в другом/том же терминале:

   ```powershell
   docker compose down
   ```

Полезные команды:

```powershell
docker ps
docker compose logs -f
docker compose down
```

## Шаг 11. Загрузи проект на GitHub

1. На https://github.com/ создай **New repository**. Назови, например, `PCFORGE_fullstack_SQLServer`. Можно оставить репозиторий пустым: не добавляй README или .gitignore, потому что они уже есть в проекте.
2. В PowerShell из корня проекта выполни:

   ```powershell
   git init
   git add .
   git status
   ```

3. Перед коммитом убедись, что в списке нет `.env`. Если `.env` случайно попал в список, остановись и не публикуй его.
4. Выполни:

   ```powershell
   git commit -m "Initial PCFORGE project"
   git branch -M main
   git remote add origin https://github.com/ТВОЙ_ЛОГИН/PCFORGE_fullstack_SQLServer.git
   git push -u origin main
   ```

   Замени `ТВОЙ_ЛОГИН` на свой логин GitHub и имя репозитория — на то, которое создал. Если Git спросит имя/почту для коммита, настрой их командами `git config --global user.name "Твоё имя"` и `git config --global user.email "твоя-почта"`.

5. Обнови страницу репозитория на GitHub. Файлы должны появиться.

## Шаг 12. Проверь GitHub Actions

1. В репозитории GitHub нажми вкладку **Actions**.
2. Открой запуск `PCFORGE CI/CD`.
3. На pull request или push workflow запускает тесты. При push в ветку `main` после успешных тестов также собирается и публикует Docker-образ в GHCR.
4. Если запуск красный, открой упавший шаг и прочитай первую красную ошибку. Исправление зависит от конкретного сообщения — не нужно угадывать.
5. Если workflow жалуется на права публикации пакета, открой **Settings → Actions → General → Workflow permissions** и разреши workflow запись в репозиторий. После этого повтори push небольшого изменения.
6. После успешного запуска проверь **Packages** на странице GitHub-профиля. Образ будет называться примерно `ghcr.io/твой_логин/pcforge_fullstack_sqlserver`.

## Шаг 13. Что показать преподавателю

Сохрани скриншоты:

1. SSMS: база `PCFORGE` и список таблиц.
2. SSMS: таблица `Components` с тестовыми комплектующими.
3. Работающий сайт `http://localhost:5000`.
4. Ответ `http://localhost:5000/api/health` со статусом `ok`.
5. Терминал с успешным `py -m pytest -q`.
6. Docker Desktop или `docker ps` с контейнером.
7. GitHub: файлы репозитория.
8. GitHub Actions: успешный workflow.
9. GitHub Packages: опубликованный образ, если этап публикации прошёл.

В отчёт/сдачу добавь ссылку на свой GitHub-репозиторий, как требует задание.

## Если что-то не работает

Не переустанавливай всё подряд. Скопируй сюда **полный текст ошибки** из терминала/SSMS и напиши, на каком шаге она появилась. Пароли, токены и содержимое `.env` не присылай.
